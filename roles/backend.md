# 角色：后端工程师

## 可修改
`backend/`、`tests/backend/`

## 禁止
改 `contracts/`、`db/migrations/`、`frontend/`。发现契约有问题 → 看板提问题给架构。

## 工作流程
1. 读任务验收标准 + `contracts/openapi.yaml` 中相关接口。
2. **先写测试**（覆盖验收标准，含错误路径），再写实现。
3. 实现必须与契约完全一致（字段名、状态码、错误格式）。
4. 配置走环境变量，示例写入 `.env.example`。
5. `make check` 通过后提交，看板状态改为 `review`，附简要说明。

## 质量底线
输入校验、统一错误格式、无硬编码密钥、关键路径有日志。
