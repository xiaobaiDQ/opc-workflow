# grill-me — 新需求结构化追问

> 适用角色：PM / GM（启用 PM 时产品目标、范围与交付口径由 PM 问，GM 只问技术选型与拆单） | 触发：新项目 / 关键选型 / 存在会实质改变目标、交付物、验收标准、架构或拆单的未定项 | 不触发：绿灯小修、单点查询、已有确认答案、可自行探查的事实

## 1. 什么时候必须用

收到老板需求后，能从 PRD/STACK/代码/实物资料查清的事实先查，**遇到待查事实时只暂缓依赖该事实的问题，其余独立问题可以先问**。以下任一成立 + 仍有会实质改变目标、交付物、验收标准、架构、契约或跨角色拆单的未定项 → 启动本 Skill：

- 新项目 PRD 核心边界、交付形态（如落地页 vs 工作台）、硬约束或实物输入不完整
- 主控/硬件 BOM/技术栈/数据契约选型
- 多端、跨角色黄/红灯需求
- PRD「已锁死」区仍出现「或、待定、后期再说、参考资料未读」

**不触发**（直接处理，不追问）：
- 明确绿灯小修、单点查询
- 已有老板确认答案且范围未变（沿用 `AGENTS.md` 第 3 节·执行 Agent 补充规则）
- 可由代码/PDF/工具链/只读实验自行查明的事实（这些该探查，不甩给老板）
- 后期项已明确「不做」且不影响本期架构（不反复追问）

## 2. 执行规则（按依赖动态追问，不凑题数）

**每轮只问前置条件已确定、且确实需要老板决定的问题。只有一个关键问题就问一个，互不依赖的问题可以一起问并附建议。收到回答后，重新判断哪些问题已解决、哪些现在可以问。遇到待查事实，只暂缓依赖它的问题。影响本期交付的决定对齐后，按现有授权推进。**

> 以下三类主题仅供按依赖排序时参考，**不要为了凑轮次或凑满 3–5 问硬把无关问题塞进一轮**。

### 参考主题 A：硬约束、实物真相与范围边界

| # | 追问方向 | 为什么先问 |
|---|---|---|
| ① | **硬约束**：题目/合同/验收里哪些字眼不可改？（例："题目里的 STM32 必须出现在实物和论文里，还是可以换 ESP32-S3 同步改题？"） | 决定后面还有没有讨论空间 |
| ② | **实物真相**：已经买好/在手/指定的器件是什么？给手册 PDF、BOM 表、原理图或实物照片。区分「已购实物 / 准备采购 / 仅教程参考」 | 直接决定用什么做 |
| ③ | **本期范围**：每个关键功能逐项——**本期做 / 后期预留 / 不做**。后期项写明本期对接的接口/引脚/协议 | 避免把后期项当成本期硬需求 |
| ④ | **补充盲区**：有没有我们该问但没问到的约束？（如学校环境、答辩要求） | 防止老板默认我们知道了 |

每问附推荐选项 + 一句话理由。老板只需选或纠正。

### 参考主题 B：路线选型（仅上游硬约束允许选时）

前提：相关硬约束和实物真相已确认。

给老板 **最多两条可执行路线**，每条说清：
- 用什么主控/技术栈/关键器件
- 对比另一条：返工面、主要风险、长期代价
- 推荐哪条、为什么

分别确认两个独立问题：
1. **「选哪条路线？」**
2. **「是否授权按此路线拆单派实现？」**（同意方案 ≠ 同意执行到底，见 `AGENTS.md` 第 3 节·老板单独确认的动作）

### 参考主题 C：演进边界（仅对已确认的后期预留项）

对「后期预留」项逐项确认：
- 本期只预留什么接口/引脚/供电/协议？（推荐最薄接口）
- 后期接入时要不要改本期已实现的代码？（目标零重构）

## 3. 输出闸门（四种状态）

| 状态 | 含义 | 后续动作 |
|---|---|---|
| **老板已确认** | 答案及来源（聊天/截图/文件）已记录 | 可据此推进拆单 |
| **待老板拍板** | 问题已提出，等答复 | **答案未确认前，不写成「已锁死」，也不派实现** |
| **待只读探查** | GM/架构师/执行者去查 | 列明谁查、查什么；仅暂缓依赖该事实的问题，其余独立问题可先问 |
| **本期不做/后期预留** | 同步写入 PRD 非目标 + 任务边界 | 不影响本期派单 |

**铁律：只要仍有「待老板拍板」的项会改变实现路线或交付物 → 只允许评估和方案比较，不允许派实现。**

## 4. 追问风格红线

- 只问当下真正需要老板拍板的关键问题，附推荐选项，不凑题数、不搞冗长问卷
- 已知答案不重复问；上次老板回答过的直接沿用
- 能自己查的事实（读代码/PDF/工具链）不甩给老板
- 老板说「你定」的项标记「老板授权自定」并记录决定，不再追问
- 老板语气口语、结论先行 → 正常，对应给出选项即可

## 5. 与现有规则衔接

| 现有规则 | grill-me 怎么配合 |
|---|---|
| `roles/gm.md` 第 1 步「先核实事实」 | grill-me 在此步骤内触发：事实查完仍有会改变架构的未定项 → 启动追问 |
| `roles/gm.md` 第 1 步「向老板确认模糊点」 | grill-me 把模糊点结构化，按依赖排序，一次问透 |
| `AGENTS.md` 第 3 节·黄/红灯方案确认 | grill-me 管「确认前问什么」，AGENTS.md 管「什么时候必须确认」 |
| `AGENTS.md` 第 4 节·变更透传 | 老板回答后，GM 同步更新 PRD/任务卡/执行工作树 |
| `AGENTS.md` 第 3 节·老板单独确认的动作 | 第 2 轮路线选型时分别确认「选哪条」和「是否授权派实现」（同意方案 ≠ 同意执行到底） |
