# 进化官审查指南

审查工作流改动、Bot 指令、Skill、外部方法或实际交付时，先回答这次要解决什么，以及下一次出现什么证据才算有效。职责和授权见[进化官角色](../roles/evolver.md)；本指南按需使用。

## 找证据与失败节点

- **已改内容**：核对影响本次结论的提交、目标分支和实际生效位置。母版、项目、执行工作树、Bot 配置与已发派单可能是不同版本。对之前的发现逐项判断已修复、仍有缺口或证据不足。
- **新点子或外部方法**：核对原文和项目现场，分清原作者的做法与本项目的延伸。用一张真实任务卡验证增量，优先借能解决具体问题的一个动作。
- **交付或执行事故**：从用户看到的结果倒查到最早可阻止返工的节点。区分缺规则、执行偏差、工具不足和传递中丢失，再选改法。

| 检查点 | 可复核的问题 |
| --- | --- |
| 进场与派单 | 项目、任务卡、工作树、执行者和实际加载的 Skill 对得上吗？旧派单是否仍在驱动执行？ |
| 关键决定 | 哪个未知答案会改变交付物、验收或权限？先解决后续决定依赖的问题，沿用已有答案。 |
| 确认与接力 | 读实际 Skill，核对提问和中间产物是否按约定转呈。用户纠偏后，执行者能否看到新版卡并按它继续？ |
| 权限与工具 | 提案、修改、执行、验收和合并分别由谁负责？实际配置和运行结果能否证明工具支持这条路径？ |
| 验证与交付 | 产物和验证证据是否对应同一版本？用户能否在自己的会话看到并使用结果？ |
| 收尾与接续 | 关键决定、最后一个已验证批次、持久产物位置和下一步能否找回？ |

分别记录**规则已写入、运行时已生效、用户已收到可用结果**。例如工具连接成功、读出场景物体、用户直接从会话看到预览，各需各的证据。只读探查抽查引用与结论；实现核对基线到交付版本的差异、产物和测试；视觉核对同版预览与实际呈现。

## 判断改多少

写清触发条件、实际行为、用户影响和证据，再判断维持现状、试跑或修订。优先找能阻断失败的现有条款。确定性检查可评估脚本化，依任务而变的视角、审美和取舍保留判断空间。产品方向和需确认动作由用户决定；已授权的执行细节由执行者选择。

提议升入母版前，拿另一类业务走一遍：同一条规则能否保护相同的业务结果，执行者是否仍能主动查证、选方法、处理可恢复的阻塞并继续推进。依赖特定工具、界面或任务步骤的做法，留在对应项目、角色或 Skill。

日常复盘可在同一会话完成。审自己参与的改动时说明参与范围，从交付和实际任务重新走一遍。形成正式提案才依[角色规则](../roles/evolver.md)发起双模型独立复核：一位查能否执行，一位查是否值得；汇报实际使用的执行器和模型、采纳与舍弃的理由。演进背景与同步方法见[演进手册](EVOLVER-HANDBOOK.md)。

交卷先给判断。重要发现附证据位置、触发条件、影响、最小改法和下一次的验证信号。需用户查看或拍板的材料随结论呈现；少量问题用短答即可。
